| 文件 | 形状 | 类型 | 说明 |

## 四、必须遵守的规则

### 1. ⚠️ 时间戳不要用 `帧号 ÷ fps`

本数据集的 MP4 头部 `nb_frames` 元数据**不可靠**：100 条中 90 条虚报，
合计虚报 30% 帧数，最大偏差 3.27 倍。

**正确做法**：用 ffprobe 读逐帧 `pts_time`。

```bash
# 已为你准备好逐帧时间戳，直接用：
handoff/vision_timing/samples/<safe_id>/vision_timestamps.npy
```

### 2. 严格递增、不超过视频时长

```python
assert np.all(np.diff(vision_timestamps) > 0)          # 严格递增
assert vision_timestamps[0] < 0.05                     # 从 0 开始
assert vision_timestamps[-1] <= duration + 0.05        # 不越界
```

### 3. 行数必须一致

```python
assert text_features.shape[0] == len(text_words)       # 词数
assert audio_features.shape[0] == audio_intervals.shape[0]
assert vision_features.shape[0] == vision_timestamps.shape[0]
```

### 4. 不要有 NaN / Inf

```python
assert np.isfinite(x).all()
```

失败的位置**保留该帧并置 valid=0**，不要删除或插值填充。

### 5. 同一模态维度在所有样本中保持一致

不能有的样本 `Da=74`、有的 `Da=80`。若有多种配置，请统一。

## 十、逐模态有效性标记（问题一自身的可核验性要求）

> **本节 2026-09-24 修订。原版把理由写成"问题二需要"，这是错的**
> —— 问题二的数据基础是附件2，不依赖问题一的产出，三问是并列的三项任务。
> 现在的理由改从题目对**问题一自己**的要求出发。

### 10.1 为什么需要它：题目明确要求"有效长度"与"掩码处理规则"

题目对问题1 的三条要求之一是：

> 二是时序组织的可核验性，包括序列位置、**有效长度**、**填充规则**
> 及其与原始素材的对应记录。

题目「数据说明」附件1 的注释又写：

> 如需在模型处理中对极短、无效或异常片段采取**掩码**、截断或其他处理，
> 应**保留原始样本**，并在报告中说明**处理规则**。

**没有有效性标记，这两条都写不清楚**：评阅人无法分辨某一段特征
究竟是真实信号、还是填充值。`alignment_trace.csv` 里记录了"哪个区间用了哪些源帧"，
但如果不知道源帧本身是否有效，追溯链就是断的。

### 10.1b 一个实测数字说明它与"数值对不对"有关

见下面 10.2 的实测：不提供标记时，一段 80% 是垃圾的区间
会被当成正常数据平均，**数值错 80% 且完全看不出来**。

### 10.2 对特征交付的具体要求

请为三个模态各提供**逐帧/逐词的有效性标记**（0/1）：

| 文件 | 形状 | 含义 | 强度 |
|---|---|---|---|
| `vision_valid.npy` | `(Tv,)` | 该视觉帧是否可用（未检出人脸 = 0，**保留该帧**） | **必需** |
| `audio_valid.npy` | `(Ta,)` | 该音频帧是否可用 | **强烈建议** |
| `text_valid.npy` | `(Tt,)` | 该词是否可用 | **强烈建议** |

**长度必须各自对齐自己的模态**：

```
len(audio_valid)  == audio_features.shape[0]   == audio_intervals.shape[0]
len(text_valid)   == text_features.shape[0]    == text_words.csv 行数
len(vision_valid) == vision_features.shape[0]  == vision_timestamps.shape[0]
```

> ⚠️ 长度不匹配会被判为**错误**（不是警告）。

#### 为什么 `audio_valid` 值得单独说明 —— 一个实测数字

这不是形式要求。如果某段音频**真的是静音或损坏**（特征全零），
不提供有效性标记时，对齐会把它当成正常数据平均进去：

```
模拟：30 帧音频，第 10~17 帧全零（中段 0.8 秒不可用）
某对齐区间恰好覆盖 10 帧，其中 8 帧全零（80%）

不给 audio_valid : 区间 mask=1（"有数据"）  均值 = [0.87, 0.91, 1.04, 1.10]
给了 audio_valid : 区间 mask=1             均值 = [4.34, 4.55, 5.21, 5.50]
只用非零帧的真值 :                          均值 = [4.34, 4.55, 5.21, 5.50]
                                              ↑ 相对差 80%
```

**三点值得注意**：

1. **数值错了 80%** —— 因为 8/10 的帧是 0，把均值拉低了一大截
2. **但完全看不出来** —— `1.03` 是个正常数值，不报错、不是 NaN、不像异常
3. **`mask` 两种情况下都是 1** —— 掩码**不会**自己变成 0 来提示"这段有问题"

也就是说：**没有有效性标记，一个 80% 是垃圾的区间会被安静地当成正常数据混进特征里。**

#### 这与题目要求的关系

题目「二、数据说明」附件1 的注释写：

> 如需在模型处理中对极短、无效或异常片段采取**掩码**、截断或其他处理，
> 应**保留原始样本**，并在报告中说明**处理规则**。

题目对问题1 的三条要求之一是：

> 二是时序组织的可核验性，包括序列位置、**有效长度**、**填充规则**
> 及其与原始素材的对应记录。

**没有有效性标记，"有效长度"和"填充规则"就无法写清楚** ——
评阅人无法分辨某一段特征究竟是真实信号还是填充值。

#### 不提供的后果（不阻断交付）

这两个文件缺失**不会**让自检失败，我也能照常完成对齐。
但请在 `metadata.json` 里说明：

```json
{
  "audio_valid_provided": false,
  "reason": "未单独导出有效性标记；全零帧即为不可用",
  "zero_frame_policy": "所有全零帧均为无效（若静音段并非全零，则此假设不成立）"
}
```

> 只要你的"真·静音"恰好也是全零，两者就无法区分 ——
> 这是**唯一**需要你确认的假设。若能确认，不提供也可接受。

---

对齐完成后，我会把逐帧/逐词的有效性**上采样到 50 个时间区间**，得到：

```
audio_mask : (50,)   # 第 j 个区间音频是否可用
vision_mask: (50,)   # 第 j 个区间视觉是否可用
text_mask  : (50,)   # 由 text_valid / text_bert 注意力掩码导出
```

**论文中报告的是这三个 (50,) 掩码，而不是三个"模态开关"。**

### 10.3 必须避免的错误做法

```
❌ 整模态 dropout：
      if random() < p: audio = zeros_like(audio)     # 整条抹掉
   这模拟的是"模态完全缺失"，与附件3 的实际缺失形态（连续时间片段遮挡）不符。

❌ 用 audio==0 判断音频缺失后再插值：会把"第 0 步恒为零"这个
   数据集固定占位当成缺失，30 个 split 全部误伤。

❌ 直接把缺失位置填 0 后送进网络，不告诉模型"这里本来就没有数据"：
   模型无法区分"信号恰好为 0"和"这里缺失"。
```

### 10.4 正确做法

1. **特征本身**照常填（缺失处填 0 或保留插值值都行）
2. **掩码单独给出**，并在融合时作为显式输入：
   `h = MLP([ x ⊙ m , m ])` —— 把掩码一并喂进去，
   让模型知道"这一维是缺失的"而不是"这一维是 0"
3. **训练时的遮挡策略**要与附件3 对齐：随机选取**连续时间段**置为缺失
   （整模态 dropout 可以作为**辅助**增强保留，但**不能是唯一手段**）
4. **阈值先冻结**：附件3/4 没有标签，掩码判定阈值必须在校验集上定好后冻结，
   不得用附件3/4 的预测结果反过来调

### 10.5 一句话总结

> **交付的是"每个时间步每个模态能不能用"，不是"每个模态在不在"。**
>
> 这条搞错了，问题二会和附件3 的实际缺失形态系统性错配。

## 十一、有 2 条视频的音轨本身没有语音 —— 请照常交付，不要特殊处理

> **本节 2026-09-25 新增。** 起因是一次接口演练：一份**完全符合本规格**的
> 100 条交付跑真实入口时，第 4 步 `align` 直接崩溃。根因不是格式错，而是
> "音轨本身没有语音"这件事在规格里没写清楚。

### 11.1 实测事实

附件1 的 100 条视频里，**有 2 条的音轨是数字静音**：

| 样本 | 真实时长 | 转写词数 | 音轨峰值 RMS |
|---|---|---|---|
| `-mJ2ud6oKI8$_$1` | 6.103 s | 13 | **1e-6** |
| `-mJ2ud6oKI8$_$2` | 5.731 s | 11 | **1e-6** |

同批其余 98 条的峰值 RMS 都在 **1e-1 量级**，判别裕度极大，不存在"把轻声误判为静音"的风险。

也就是说：这 2 条**有画面、有转写文本，但没有任何可观测语音**。

### 11.2 你要做的：什么都不用改

**照常提取、照常交付全部文件、不要删除这 2 条样本。**

- `audio_features.npy` / `audio_intervals.npy` 照常给（值会接近全零，没问题）
- `audio_valid.npy`：按你的判据给即可，**不需要**为了这 2 条刻意置 0
- `text_features.npy` / `text_words.csv` / `vision_*.npy` 全部照常给
- `run_log.csv` 里可以记一句备注，但**不要**把状态标成失败

**我会在对齐侧自行判定**（用 ffmpeg 解出的帧能量峰值，阈值 1e-5），并把这 2 条样本：

- 音频与视觉通道全部置为不可用（掩码 0）
- **文本通道仍然保留并有效**（文本是按词索引分组，不依赖时间）
- 时间字段全部填 `-1.0` 哨兵，不编造边界

**结果文件仍然是 100 条**（题目要求"保留原始样本"，也要求 100 条覆盖完整性）。

### 11.3 如果你在提取时遇到它们，请不要做这些事

```
❌ 删掉这 2 条样本（会让交付从 100 条变成 98 条，违反覆盖完整性要求）
❌ 拿其它样本的音频去替换或补齐（伪造数据）
❌ 给它们编一组"看起来合理"的时间轴（这正是我们刚修掉的一个缺陷）
❌ 因为"工具没返回有效特征"就把整条样本标为失败（它只是没有语音，不是提取失败）
```

### 11.4 顺带说明：为什么"覆盖率 1.000"掩盖得了这个缺陷

我们的对齐算法此前会给这 2 条样本也输出一组**严格单调、落在时长范围内、
覆盖率恰好 1.000** 的时间轴 —— 每一个结构性检查都通过，覆盖率指标也看不出问题，
因为覆盖率只回答"被覆盖了多少"，从不问"被对齐的那段到底有没有声音"。

所以现在把"音轨有没有信号"做成了**准入条件**而不是事后检查项。
这条同样适用于你的提取流程：**如果某个环节的输入本身可能为空，先判空，再计算。**

## 十二、`text_words.csv` 必须与 `handoff/q1_expected_words.csv` 逐行一致

> **本节 2026-09-25 新增。** 起因是一次用户的追问：接口演练用的是我们自己生成的
> `text_words.csv`，所以**"词轴对不对"这条根本没被验证过**。查下去发现，
> 分词不一致的后果是**静默**的。

### 12.1 为什么这一条是硬要求

对齐程序把 `text_features.npy` 的**行**映射到**我们的**词序号上；而我们的词序号来自
我们自己的分词器（规则：连续的字母数字，允许内部一个引号，即 `They've` 是一个词）。
两边不一致时：

| 情形 | 后果 |
|---|---|
| 你的词数 **多于**我们的 | 程序报错，直接退出（很好） |
| 你的词数 **少于**我们的 | 尾段词拿不到文本特征，掩码静默变成 0 —— **不报错** |
| 词数相同但**切分不同** | 每一行特征都贴到**别的词**上 —— **完全静默** |

后两种以前没有任何检查能发现。现在它们会被 `validate-handoff` / `import-handoff`
**直接拦下**，并指出第一个不一致的位置。

### 12.2 你要做的

`handoff/q1_expected_words.csv` 是**我们的规范分词结果**，字段：

```
sample_id, safe_id, word_idx, word
```

- 文件是**纯 CSV**（无注释行、无空行），首行就是表头，共 1934 行数据；
  直接 `pandas.read_csv` 即可，不需要任何 `comment=` 参数；
- `word_idx` 必须是 `0..N-1`，**按文件顺序**；
- 第 `i` 行的 `word` 必须与表中同一 `sample_id` 的第 `i` 行一致；
- 只有**排印差异**（弯引号 `’` / 反引号 / 大小写）被视为等价，不会拦截。

如果与你的分词结果不同，**以这份表为准**再做一次分词即可 ——
它就是我们做词级时间定位时用的那一套，两边必须完全对上。

### 12.3 这条闸门是**验证过**的，不是摆设

我们故意破坏词轴的四种方式，全部被 `validate-handoff` 拦下（未破坏的对照组正常放行）：

| 改动词形（切分不同） | ✅ `word sequence differs ... at 1 position(s)` |
| 打乱 `word_idx` | ✅ `word_idx must be 0..N-1 in file order` |
