## 五、🆕 本轮新发现（陷阱清单里还没有的 8 条）

### 5.1 🔴 音频轨系统性短于视频轨，但 `D` 取的是视频轨时长
- 实测 **99/100** 的音频轨比视频轨短，中位 **100 ms**、最大 **180 ms**（`-s9qJ7ATP7w/4.mp4`）
- 我方 `manifest.jsonl` 的 `duration_sec` = `video_stream_duration`，词级对齐把 `[0, D]` 铺满 → **最后一个内容位的音频只覆盖了它区间的一部分**
- 危害：论文写"有效长度与填充规则"时，评阅人只要把音频轨时长和视频轨时长一比，就会发现存在未解释的空隙
- 正解：**主时间轴改取 `D = max(音频轨时长, 视频轨时长)`**（重跑词级对齐仅 9.2 s），并**新增逐位置 `audio_coverage_ratio`**，与已有的 `vision_valid_ratio` 对称

### 5.2 🔴 队友论文的"音视频轨道时长最大相差约 155 毫秒"是错的
- 队友 §4.3.4（原文）："原始视频核查显示，音视频轨道时长最大相差约 **155** 毫秒"
- 实测：max **180.0 ms**、中位 **100.0 ms**、均值 103.8 ms；**>155 ms 的只有 23/100**
- 处置：改为实测值，并补上中位数与样本数

### 5.3 🟠 `qc_report.csv` **缺 `coverage` 与 `words_per_second` 两列**，与文档声称的"四级可核验 QC"不符

## 七、最终版对齐规则（冻结 · R1–R9）

> **v2.1 修订（2026-09-25，第 27 轮）**：采纳第三方对本文对齐部分的 6 条质疑，
> 逐条实测后改了 3 条规则（R1 扩展、🆕 R8 静音准入、🆕 R9 帧轴边界），
> 另 2 条补成可核验字段、1 条被实测收窄。改动依据见 §十二。

### R1 时间基准
- 逐帧时间戳取自 **ffprobe 的 `pts_time`**，禁用 `帧号 ÷ fps`、禁用 `cv2.CAP_PROP_FRAME_COUNT`
- 主时间轴 `[0, D]`，**`D = max(容器时长, 视频轨时长, 音频轨时长, 末帧pts + 1/fps)`**
  （v1.0 → v1.1 只取 max(视频, 音频)；🆕 v2.1 再纳入容器时长与**帧轴末端**）
- 为什么必须纳入帧轴末端：实测 **9/100** 条视频的 `末帧pts + 1/fps` **严格超过**其它三个上界，
  最大 **+100.0 ms**（`-571d8cVauQ$_$0`：帧轴末端 5.1667 s，其它上界 5.0667 s）。
  只取容器/流时长会让**尾帧没有归属**，且这个缺口正好落在词边界最不确定的尾部
- 为什么**不必**考虑帧轴起点：实测**首帧 `pts` 非零 0/100**（原先记录的"10/100 起点偏移"是错的，
  那个 0.100 s 是尾部不是头部，见 §十二「被推翻 1 条」）
- manifest 记录：`container_duration_sec`、`video_stream_duration`、`audio_stream_duration`、
  `frame_count`、`fps`、`last_frame_pts`、**`frame_end_sec`**、**`frame_end_excess_sec`**、
  **`first_frame_pts`**、**`head_gap_sec`**、**`tail_gap_sec`**、`declared_frame_count`、`frames_match`
- 🆕 **容器结构** 也逐条记录：`has_edit_list`、`edit_list_count`、`edit_list_entries`、
  `movie_timescale`、`edit_segment_sec`、`movie_duration_sec`。实测 **100/100** 条带 `elst`
  （每条轨道 1 个、共 2 个）；把 `segment_duration ÷ movie_timescale` 后与对应流时长比对，
  **200 个片段最大偏差仅 0.667 ms** → 证明 ffmpeg 已按**呈现时间轴**解码，我们读的 `pts_time`
  就是呈现时间（这是"为什么可以信任 pts"的可核验依据，不是一句注释）
- ⚠️ **`mvhd.duration` 不是时间来源**：实测 **99/100** 条高于容器真实时长
  （中位 +3.11 s、最大 +8.29 s）——它与 `nb_frames` 同源，都是**裁剪前**的旧值

### R2 位置轴
```
max_positions = 50
位置 0        = [CLS]
位置 1..n     = 内容位，n = min(词数, 48)
位置 n+1..48  = 填充位
位置 49       = [SEP]
effective_length = n + 2
```
- 词数 > 48 时用 `numpy.array_split` **按顺序均匀合并**为 48 组，**覆盖完整文本、不丢尾部**（实测 2/100 条触发）
- 该设计与附件2 `aligned_50` 的语义同构（实测附件4：内容位置数 11–48 ≠ 恒定 50，与"每词一位 + 首尾特殊 token"吻合，偏移恒为 2、corr 1.000）

### R3 词级区间
在 `[0, D]` 上求 `0 = b₀ < b₁ < … < b_T = D`：
```
min  Σ_t w_t · ( (b_t − b_{t−1}) / ŝ_t − 1 )²  −  λ · Σ_t P(b_t)
s.t. b₀ = 0, b_T = D                      (完整覆盖)
     b_t − b_{t−1} ≥ ε = 0.02 s           (严格单调)
     T / D ∈ [1, 6] 词/秒                  (生理合理)
```
- `ŝ_t`：音节感知的期望时长（元音组计数，功能词 ×0.75 弱读衰减）
- `P(·)`：±80 ms 邻域的能量谷奖励
- 求解：初值累积分布 → 约束投影（顺序前推 + 逆序回拉）→ 停顿精化（α=0.5）→ 重新投影
- 🆕 **R3 的前置条件**：上式**只在音轨存在可观测语音时**才有意义，见 R8

### R4 跨模态聚合（**主规则，附消融**）
- **主规则**：源帧**中心**落入 `[b_{k−1}, b_k)` 者归入该位置，取**等权均值**
- **消融对照**（三行，进论文表格）：
  1. 帧中心落入 + 等权（本文）
  2. 重叠时长加权（时间积分）
  3. 均匀切分 `j·D/50`（朴素做法）
- **裁决理由（量化过，不是感觉）**：M1 实测该规则产生 **0/1910** 假缺失（可发声样本）；
  M2/M3 显示最短词区间 63.65 ms ≈ 1.9 个视频帧，因此"丢边界帧"的差异被限制在 **≤1 帧**；
  而词边界本身的不确定度是**停顿窗 ±80 ms ≈ 2.4 帧**。
  **即规则之争的差异比对齐自身的不确定度小一个量级** —— 因此保留低复杂度、
  已被 C10 逐值复算确认的实现，把另一种规则作为消融报告，比换实现更有价值
- 空区间（无帧中心落入）→ 该位置该模态 `mask = 0`（实测 0 次）

### R5 掩码与覆盖率（**四类掩码 + 三类覆盖率**）
| 输出 | 形状 | 含义 |
|---|---|---|
| `sequence_mask` | (50,) | 真实序列位置（CLS + 内容 + SEP），填充位为 0 |
| `text_mask` | (50,) | 该位置文本是否有有效特征 |
| `audio_mask` | (50,) | 该位置音频是否有有效帧 |
| `vision_mask` | (50,) | 该位置视觉是否有有效帧 |
| `vision_valid_ratio` | (50,) f32 | 该位置内**源级视觉有效帧**占比（区分"没有人脸"与"数值恰为 0"） |
| `audio_coverage_ratio` | (50,) f32 | 该位置内**落在音频轨时间范围内**的比例（应对 5.1） |

### R6 哨兵与追溯
- 无时间映射的位置：`interval_start = interval_end = −1.0`，且**与 `mask = 0` 严格一一对应**（guard C9 机检）
- 🆕 **静音样本的每一个词时间都必须是 −1.0**，且 `mask` 全为 0（R8）；这条把 R6 从"少数无映射位置"扩展到"整条样本无映射"
- 逐样本 `provenance.bins`：`position / word_start_index / word_end_index / text / start / end / text_feature_indices / audio_feature_indices / vision_feature_indices` → 落盘为 `alignment_trace.csv`（段023「与原始素材的对应记录」）

### R7 不变式（全部可机检，进 `guard_check`）
1. 覆盖率 `(b_T − b_0) / D = 1.000`（容差 1e−9）—— **仅在可发声样本上**，静音样本按 R8 排除
2. `b_0 = 0`、`b_T = D` 精确（实测 **98/98** 可发声样本）
3. 相邻词区间不重叠、不越界
4. 语速 ∈ [1, 6] 词/秒
5. `effective_length == n_content + 2`，且 `n_content ≤ 48`
6. `mask == 0  ⟺  interval_start == −1.0`
7. 文本/语音/视觉三路特征行数与源数据行数一致
8. 每个内容位的 `audio_coverage_ratio` 与 `vision_valid_ratio` 均被显式记录（不得缺失）
9. 🆕 静音样本的 `audio_present == False` **必须** 与 `energy_peak ≤ 1e-5` 一致，
   且 `final_usable == False`、`alignment_method == "audio_absent"`、
   QC 状态为 `audio_absent`（guard C15）
10. 🆕 每个 `elst` 片段除以 `movie_timescale` 后必须与其对应流时长相差 ≤ 2 ms（guard C16）
11. 🆕 `duration_sec == max(容器, 视频, 音频, 帧轴末端)` 必须可**单独复算**（guard C17）

### 🆕 R8 静音准入（v2.1 新增，来自第三方质疑 C1）

**规则**：对齐开始前先算整条音轨的**帧能量峰值**；只有峰值高于 `SILENCE_PEAK_FLOOR = 1e-5`
才允许进入 R3 求解。

**为什么这条比其它规则都重要**：

| | 旧实现 | 现实现 |
|---|---|---|
| 安静音轨 | 照样输出一组**严格单调、落在时长内、覆盖率 1.000** 的边界 | 每个词时间填 **−1.0 哨兵**，`final_usable=False` |
| 通过的结构性检查 | 全部通过（单调 ✓ 有限 ✓ 在时长内 ✓） | — |
| 覆盖率指标 | **1.000**，看不出任何异常 | 不参与统计（无时间可算） |
| QC 状态 | `pass` | **`audio_absent`**（独立状态，不得混入 `awaiting_features`） |

**实测证据**：`-mJ2ud6oKI8$_$1`（13 词）与 `-mJ2ud6oKI8$_$2`（11 词）的峰值 RMS 只有 **1e-6**，
比静音底线低一个数量级，而同批素材里其余 98 条的峰值均在 **1e-1 量级**——判别裕度极大，不存在"把轻声误判为静音"的风险。

**为什么"覆盖率 1.000"掩盖得了这个缺陷**：覆盖率只回答"被覆盖了多少"，
从不问"被对齐的那段到底有没有声音"。所以 R8 必须是一条**准入条件**，
不能做成事后检查项。

### 🆕 R9 帧轴边界（v2.1 新增，来自第三方质疑 C3）

**规则**：`D = max(容器时长, 视频轨时长, 音频轨时长, 末帧pts + 1/fps)`，
且每个上界都逐样本落盘，使"`D` 是怎么来的"可以**不看代码单独复算**。

**为什么**：实测 9/100 条视频的帧轴末端严格超过其它上界（最大 100.0 ms）。
这 100 ms 相当于 3 个视频帧，足以让**最后一个词**的区间落在没有帧覆盖的空档里——
而尾部恰好是词边界最不确定的位置（停顿吸附窗 ±80 ms）。

**同时记录否定结论**：`first_frame_pts`、`head_gap_sec` 实测全为 0，
即"帧轴起点偏移"在这批素材上**不存在**。记录否定结论的价值在于：
下一个看到"帧轴两端都可能偏移"的人不必再猜我们查没查过。

### 12.5 这次改造最值得记住的一点

C1 抓到的不是"某个数字算错"，而是**"每个检查都通过"**：
旧实现在静音音轨上输出的时间轴**严格单调 ✓、落在时长内 ✓、覆盖率 1.000 ✓、有限性 ✓**——
所有结构性检查全绿。**唯一能拦住它的办法，是把"输入本身有没有信号"变成一条准入条件**，
而不是事后加一个检查项。这与第 4 轮 H3 的教训同构：**指标只能在它定义的坐标系里发现异常**，
覆盖率这个坐标系里根本没有"有没有声音"这一维。
